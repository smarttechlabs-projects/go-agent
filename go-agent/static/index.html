How the Agent Loop Works

The agent orchestrates a loop between the LLM and MCP tool servers until the LLM produces a final text answer.

The Loop

1. User sends a message
2. Agent sends message + tool definitions to LLM
3. LLM responds with either:
   a) tool_calls -> agent executes tools
      -> results appended to history
      -> go to step 2
   b) text only -> loop ends
4. Final text returned to user

When Does the Loop End?

  • The LLM returns a response with no tool_calls -- just text content
  • The maximum round limit (10) is reached
  • A tool fails repeatedly (2+ times) -- the LLM is told to answer from its own knowledge
  • The user cancels with Ctrl+C

What Each Box Shows

  • LLM Request -- messages and tools sent to the model
  • LLM Response -- what the model returned, with TTFT, tokens, and throughput
  • Tool Call -- which tool the LLM chose and with what arguments
  • Tool Result -- what the tool returned

Click Input or Output on any box to inspect the full token content.

Metrics

  • TTFT -- time to first token (streaming latency)
  • Tokens -- prompt + completion token counts
  • tok/s -- generation throughput
  • Elapsed -- total step duration

Active Safety Limits

Server-configured caps. Clients can request stricter limits per-query (via REST limits body field or MCP _meta with io.llm-agent/ prefix) but never looser.
